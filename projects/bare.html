Bare-Metal STM32F407VET6 GPIO Controller (No HAL)

Engineered a functional General-Purpose Input/Output (GPIO) controller entirely from scratch, intentionally bypassing the Hardware Abstraction Layer (HAL) to develop a foundational understanding of the underlying ARM Cortex-M hardware architecture and memory-mapped I/O.

The implementation was written purely in C, utilizing direct pointer manipulation to interact with specific memory addresses derived from the STM32 Reference Manual (RM0090) and the board's hardware schematics.

Hardware & Implementation Strategy

The core objective was to bridge physical hardware schematics with low-level firmware initialization, resulting in functional LED toggle control based on physical pin states.
  • [Hardware Target] Executed on an STM32F407VET6 development board.
  • [Clock Configuration] Manually enabled the peripheral clock by configuring the Reset and Clock Control (RCC) registers.
  • [Pin Configuration] Set the required input and output modes using the GPIO MODER registers.
  • [Control Logic] Established the software logic by continuously polling the Input Data Register (IDR) and writing the resulting output state to the Output Data Register (ODR).

Validation & Debugging

Hardware behavior was validated through direct manipulation and real-time monitoring to ensure exact register compliance.
  • [Physical Interaction] Altered the input state manually by jumping a pin on the board to trigger the control logic.
  • [Live Hex Monitoring] Conducted live debugging sessions via an ST-LINK V2 interface.
  • [Verification] Observed raw register hex values updating dynamically in the IDE, perfectly mirroring the physical state changes and confirming the successful execution of the custom bare-metal driver.
